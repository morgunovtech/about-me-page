# CLAUDE.md — about-me-page

Personal homepage for Semyon Morgunov, deployed on Cloudflare Pages.

## Stack

- **Pure static HTML/CSS/JS** — no framework, no build step, no npm
- **CSS Custom Properties** for theming (4 themes: light, dark, auto, high-contrast)
- **Vanilla JS** wrapped in an IIFE, ~320 lines: theme, one generic dropdown controller (mobile nav / language / theme), anchor smooth-scroll, the 404 page's client-side EN copy. No scroll listener: the side column, «↑» and the progress bar are gone (v0.31.1–v0.31.2)
- **Cloudflare Pages** for hosting with `_headers` and `_redirects` config files

## Deploy Process

**GitHub → Cloudflare Pages (automatic)**

1. Push to `main` branch on GitHub (`morgunovtech/about-me-page`)
2. Cloudflare Pages detects the push via GitHub integration and deploys automatically
3. No build command — files are served as-is
4. `_headers` and `_redirects` are processed by Cloudflare automatically

There is no build step and no deploy pipeline of our own — Cloudflare Pages deploys on push. GitHub Actions only check, never deploy: `ci.yml` runs on every PR and on every push to `main` (`scripts/check.sh`, the Functions build, gitleaks over the whole history); a separate workflow, `dependabot-automerge.yml`, auto-merges Dependabot minor/patch bumps once CI passes.

### Release flow

1. Work on a branch (worktrees under `.claude/worktrees/`); `main` is production.
2. `python3 scripts/version-stamp.py` when any stamped asset changed, then `scripts/check.sh` (full, with the Functions build).
3. Add the `CHANGELOG.md` entry (next version — see Versioning) in the same commit.
4. Push the branch → `gh pr create` → squash-merge. Every push also builds a Cloudflare **Preview** deployment for the branch.
5. Verify production, not just the merge: `npx wrangler pages deployment list --project-name about-me-page` shows the Production row for the commit; then check the live page (the `x-build` response header of a page is the deployed commit — the footer shows the version; Function-rendered HTML sits in the edge cache up to 300 s — look at `x-edge-cache`).
6. Read-only checks of real content: `npx wrangler kv key get --binding CONTENT "s.morgunov.tech:<page>" --remote` (KV wins over `content.seed.json`).
7. A content change made in the seed reaches the live page only through KV: after the merge the owner runs `node scripts/kv-push.mjs <page>` (dry run: every field that changes) and then `--yes` — agents cannot write production KV. Notes have no seed at all: a proofreading pass ends in a patch file under `scripts/patches/`, applied by the owner with `node scripts/kv-patch-notes.mjs <file>` (dry run, then `--yes`).

Accounts: `gh` (morgunovtech, `repo` scope) and `wrangler login` (OAuth, expires — re-run `npx wrangler login` when `whoami` says not logged in). Secrets are set by the owner with `wrangler pages secret put`, never by an agent.

### Versioning

SemVer on the `CHANGELOG.md` versions:
- **patch** — fixes, copy and content corrections, docs, config;
- **minor** — a new feature or section that leaves the page map intact;
- **major** — the page map or the public contract changes: sections, anchors or URLs removed or renamed, a contact channel dropped, a page hidden.

From v1.0.0 (2026-11-09, site v2) every release gets an annotated tag `vX.Y.Z` on its squash-merge commit; minor and major releases also get a GitHub Release with English notes (the CHANGELOG entry stays the detailed record). v0.1–v0.31.5 were untagged.

### One-command verification

`scripts/check.sh` runs everything below in order: `node --check` on all JS, `node --test`, RU↔EN sync, critical-CSS drift, the `chrome.js` twin check, the static-twin check, the static-typography check, and (unless `NO_BUILD=1`) `wrangler pages functions build`. Run it before every commit.

### RU↔EN sync check

`scripts/check-sync.py` verifies that the eight RU and EN HTML pairs (`index.html`, `consulting.html`, `collaborate.html`, `uses.html`, `privacy.html`, `thanks.html`, `social-tracker.html`, `tofsdevops.html` ↔ their `en/` twins) share the same DOM structure (tag tree + classes + ids). It ignores text, attribute values, and state classes (`is-active`).

Run before commit when touching layout:

```sh
python3 scripts/check-sync.py            # summary
python3 scripts/check-sync.py --verbose  # full mismatch list
```

Exit code 0 = sync, 1 = drift detected.

### Static twins (templates ≡ seed render)

Every hook of the committed HTML holds what the edge overlay puts there for `content.seed.json`: the `data-cms-list` containers and the `data-cms-jsonld` script (the renderers' output) and, since v4.1.0, the leaves hooked one by one — `data-cms-text`, `-md`, `-html` (an element's content) and `-content`, `-href`, `-alt`, `-abs` (an attribute); until then 31 leaves had drifted unnoticed (a title, a hero line, share cards). That twin is the fallback when KV is empty or an overlay handler throws, and it is what a plain static preview shows. `scripts/render-static.mjs --check` fails when a template drifted; `--write` regenerates it in place. An invisible character is written as its entity (`&nbsp;`, `&#8209;`, `&#8288;`) — one typed into a template as the character itself counts as drift. The twin is the stored text: the typography pass is the edge's. After any change to `content.seed.json`, `functions/_lib/render.js` or `functions/_lib/jsonld.js`: run `--write`, then `check-sync`.

### Static pages are typeset in the file

`/thanks`, `/social-tracker`, `/tofsdevops`, `/404` and the footer of every page are hand-written text that no renderer builds and no overlay touches. `scripts/typo-static.mjs --write` runs the site's typography pass (`typo()` in `functions/_lib/markdown.js`) over them and writes the no-break spaces into the files as entities; `--check` (in `check.sh`) fails when one is not typeset. Run `--write` after editing that text. A static page stays under 14 KB compressed (`tests/site-nav.test.mjs`): since June 2025 Russian ISPs cut every Cloudflare response after about 16 KB of transferred bytes.

### Critical-CSS drift check

`scripts/check-critical.py` re-parses the inline `<style>` block of every page and
compares each declaration against the external layer (`ds/v1/*.css` + `styles.css`).
A declaration present on both sides with **different values** is an error (exit 1) —
that's the drift class that shipped visible bugs twice (v0.23, v0.28). Inline-only
declarations are warnings (`--verbose` to list, `--strict` to fail on them). Run it
together with check-sync before committing anything that touches CSS.

## CSS Architecture

- **Design system of record:** the Claude Design project «morgunov.tech Design System» (imported from this repo). Its rules bind here: `border-radius: 0` (the one round shape is the live dot with its two relatives, the busy mark of a button and the selected-item mark of a menu) and `box-shadow: none` everywhere, no gradients, no emoji, no content icons (the subscribers stat reads `TG · LI · YT · IG`), no font-weight 700.
- **Tokens are colours + type only:** the `--v4-*` colour set per theme on `[data-theme]` (+ `auto` via `prefers-color-scheme` for consumers without the inline script), `--v4-sans`/`--v4-mono`, the `--v4-label-*` settings. Sizes, gaps and durations are literals in the CSS — do not add `--space-*`, `--radius-*` or `--shadow` twins.
- Shell max width 1280px, padding 32/48/48 (24/32/40 up to 960px, 16/20/32 up to 640px); responsive breakpoints: 480px, 640px, 800px, 960px, 1100px
- **Type — one voice** (v4.1.0; the head comments of `ds/v1/components.css` and `styles.css`, `tests/composition.test.mjs`). Every size on a page is one of: the page title `clamp(40px, 6.2vw, 56px)` (a phone: `clamp(32px, 10.6vw, 40px)`) — one style for the homepage, a subpage, the publications and a topic (`.v4-h1`); a note's title 40/34/28; a section title 24 (20 on a phone); an item title 18 (a card, a note in a feed, a kit row); **16 for anything read as a sentence, on every device and in every theme** (`body.v4-page`; it was 14 on a desktop); 18 for the hero lead and a note's body (16 on a phone); 14 for a secondary line (a role, an arc, a source, a reply time, the kit's facts, the on-page line, the topic line, the footer, a version, a count, a price); 13 mono for the label column of a table; 12 caps for a caption. **Weight says the role:** 600 a title or a name, 500 something to press (the bar, a button, a link title, a «more» link), 400 text. **One caption style** (tokens.css): sans caps 12px / 0.08em / `--v4-label-weight` (500) — the bar, the menus, the buttons, the hero eyebrow, `.v4-h3`, a card's `.v4-tag`; `--v4-label-xs-*` holds the same values (both names stay for the stylesheets and the `ds/v1` consumers). **Mono is the label column of a table** — a period, a year, a date, with its source on the homepage's feed (`.period`, `.year`, `.v4-feed-meta`, `.v4-note-date`) — plain, never caps, never a link; there is no mono caps anywhere (v1.3.0–v4.0.1 had two caption styles side by side, sans caps and mono caps). A number inside a line of text is set in the line's own face: a version in the head of a card, a count after a topic, the build mark in the footer (they were mono until v4.1.0 — a second face in the middle of a sans line). Inline `code` is the one other mono: a step under its text (14px in 16px text, 16px in a note) on a quiet ground with a hairline — one idiom on a page and in a note. A price is the secondary fact in the head of its card; where the amount is marked in the doc (`**$300** / сессия`) it alone is 16px / 600 ink. No italics in the chrome: no rule of the layer sets `font-style: italic`. Italics are the author's emphasis in a note (`<em>`, and `<em>` inside `<strong>`), set in real faces since v4.1.1 — IBM Plex Sans Italic 400 and 600, Latin and Cyrillic (until then the family shipped none and a browser slanted the upright face itself). There is no 500 italic and no mono italic; no page preloads an italic face — a browser fetches one only on a note that uses it. The one text under 12px is the footer nameplate (11px).
- **Space** (v4.1.0): every gap is one of 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64. Between sections 64 (48 on a phone), under a section head 24, between paragraphs 16 (24 in a note's 18px text), a row of a table 16 (one line) or 24 (several lines), a card's padding 24 (16 on a phone). A grid of cards keeps the width of its columns in every row — a short last row leaves room after it, and the gutters of the rows stay on one line. **One grid for every «label | content» table** — the career, the ventures, the feeds, the notes: the first column is 160px, the gap 24px; they fold into one column at 640px (the career keeps its third column from 961px).
- **Measure:** `.v4-prose p`, `.v4-list li` and card copy stop at 62ch.
- **Only controls answer the pointer:** `.v4-product` and `.v4-use` have no `:hover`. `.v4-btn` (44px high; `.v4-btn--sm` is 32px with a 44px hit area) answers the pointer and the focus with the ink fill — the primary one too (it used to lighten its orange by 6%: an answer nobody saw) — and has a pressed look (`:active`), a disabled one (`:disabled` / `aria-disabled="true"`: dashed outline in `--v4-dim`) and a busy one (`.is-busy`: the pulsing dot before the label). Under `@media (hover: none)` hover paints nothing, so a tapped button does not stay inverted.
- **Service chrome:** a family service repeats this site's bar, language and theme menus and footer — the markup snippet and the rule are «Service chrome» in `ds/v1/USAGE.md` (`tests/chrome.test.mjs` keeps the snippet whole). `.v4-service` in `components.css` is the mark «MORGUNOV.TECH / NAME» that a service puts at the left of the bar; this site has none — it is the family.
- **CSS delivery:** the five stylesheets (`ds/v1/{fonts,tokens,base,components}.css`, `styles.css`) are plain render-blocking `<link rel="stylesheet">` (immutable, content-hashed). The inline critical block is only tokens + body + skip-link. Fonts preload 400/500/600 sans (cyr+latin on RU pages, latin on EN) and mono 400 (+ mono 500 on every page but 404); the italic faces are never preloaded.
- **Hero:** two columns from 641px — the text and the portrait (`clamp(200px, 30vw, 360px)`), one column on a phone; `.v4-hero--simple` (a page without a portrait) is the same block. The gap over the hero's buttons belongs to the buttons, so a page without any leaves no hole.
- **Arrows.** The IBM Plex subsets carry no arrow but ↑ ↓ (and no «₽»): a «→» in a line comes from the system font, which is fine, but a system «↗» is a hairline from a symbol font. So the mark of a link that leaves the site is the line's own «→» turned 45° — `outMark()` / `NE_ARROW` in `_lib/i18n.js`, `.v4-ne` in `components.css`; the character «↗» is never emitted (`tests/composition.test.mjs`). The turned arrow is a box, and a line may break before a box even after a no-break space (measured: the arrow started a line alone at 30 window widths of 230): the mark is a no-wrap span (`.v4-out`) that opens with a word joiner, and the gap before the arrow is its margin — the arrow stays with the last word, and a link's underline ends at that word.
- **Typography pass** (v4.1.0, `typoText` / `typo` in `_lib/markdown.js`): on the public render only — `overlay.js` (not in the editor, where the text on the page is the text of the doc, and not in `<title>`), the notes index and the note shell — a hyphen after a one-letter prefix does not break («e‑com»), a «·» and a «—» stay with the word before them, and in Russian a one- or two-letter preposition, conjunction or «не» / «ни» stays with the word after it; a number that stands on its own stays with the word it counts («10 лет», «4 работают» — not the tail of an address or a version, and not before a function word), a group of thousands with its number, a range does not break after its dash, an arrow stays with its word. Text only: never a tag, an attribute, `<code>` or `<pre>`. An inline tag does not hide a rule from its neighbours («в **Skyeng**», a venture's «· Founder»), but two elements side by side are not one phrase: between them only a separator is tied (the count of one topic link is not the number of the next link's word — that chained the topic line into one unbreakable string). The static pages are typeset in the file (`scripts/typo-static.mjs`, above). In the source the invisible characters are escapes or `String.fromCharCode`, never the characters themselves.
- `font-size` and `line-height` are set on `body.v4-page` (`ds/v1/base.css`, and the inline critical block of every page): 16px / 1.6 in every theme
- `@media (prefers-reduced-motion)` block is intentionally placed **at the end** of `styles.css`
- Sections are rendered as written: no `content-visibility` (removed in v4.1.0 — the containment it turns on clipped the focus ring of every link and button on a section's edge, and a dozen short sections had nothing to win from deferred rendering)

## Theme System

- Theme is set via `data-theme` attribute on `<html>` (NOT body)
- `script.js` stamps `data-js` on `<html>`; `components.css` keeps a `:focus-within` fallback that opens the dropdown panels until it does (progressive enhancement — language switch and mobile nav work without JS)
- Inline `<script>` in `<head>` reads localStorage and sets `data-theme` on `<html>` before body is parsed — this prevents FOUC
- `<body>` starts with `class="no-transition"` to suppress the 300ms background/color transition on initial load; `script.js` removes this class after the first paint via double `requestAnimationFrame`
- `script.js` manages theme switching at runtime, writing `data-theme` to `document.documentElement`

## Important Rules

- **No build tools.** Do not add npm, webpack, Vite, or any bundler. Keep it zero-dependency.
- **No frameworks.** Do not introduce React, Vue, Alpine, or any JS framework.
- **Accessibility first.** Every interactive element must have proper ARIA attributes. Maintain `focus-visible` styles. Respect `prefers-reduced-motion`.
- **Theme compatibility.** Any new UI element must work correctly in all 4 themes (light, dark, auto, high-contrast). Use CSS variables — never hardcode colors or shadows.
- **External links** must always have `rel="noopener noreferrer"` and `target="_blank"`.
- **Hero image** uses `loading="eager" fetchpriority="high"` and is preloaded in `<head>` — it is the LCP element and must not be lazy-loaded. All other images should use `loading="lazy"`.
- **Privacy.** No cookies, no trackers, no analytics scripts. The footer explicitly states this — don't break that contract.
- **Bilingual.** Russian is primary (`/`), English is at `/en/`. Both pages share the same `styles.css` and `script.js`. Keep content parity between them.
- **Semantic HTML.** Use `<article>`, `<section>`, `<nav>`, `<main>`, `<footer>` appropriately. Maintain heading hierarchy.
- **CTA convention.** In any button row the primary button comes first. «←» is reserved for back-links to the parent page (always secondary, last); a trailing «→» marks actions that leave the site or start a flow (book, install, check, «узнать подробности»); plain contact buttons (Telegram, «На главную») carry no arrow. A contact labelled as the start of a process («Написать →», «Send a pitch →») is a flow and keeps its arrow. A «more» link (`.v4-more`) is not a button: sentence case, 16px / 500, an orange line under the words (not under the arrow); its label names what is behind it («Все проекты на GitHub», never «Подробнее») and carries no glyph — `moreLink()` adds «→» for a page of this site and the «↗» mark (`outMark()`) for a link that leaves it. **One label for one action** (v4.1.0): every button that opens the Telegram chat reads «Написать в Telegram» / “Message me on Telegram” — a hero, a tier, a contact panel, «Сообщить об ошибке» (`tests/stage3.test.mjs`); a button that leads elsewhere keeps its own words. A bar link under the pointer takes the full ink and nothing else: the orange underline is the sign of the current page alone.

The address appears in exactly four places: the home «Связаться» panel (a line of text under the Telegram button, never a second button — v1.5.0), the `/collaborate` contact (v4.7.0, the owner's brief: a company's PR need not use Telegram — there the e-mail is the button and Telegram the line under it), the `llms.txt` Contact list and JSON-LD `Person.email` (`home.seo.email`). The cover fills the frame, cropped from its upper part (`object-fit: cover`, `object-position: 50% 25%`); a picture in the text — a screenshot, a scheme, a photo — is fitted whole and never enlarged (`object-fit: scale-down`), as the hardware photos on `/uses` are: cropping it would cut what the note talks about (`tests/composition.test.mjs`).

- **No inline scripts in `<body>`** — only the one in `<head>` for FOUC prevention. The 404 page's EN copy is driven by `data-i18n-*` attributes handled in `script.js`, not by an inline script.
- **Every executable `<script>` carries `data-cfasync="false"`** (the FOUC script, `script.js`, `admin-app.js`, the notes shell). Cloudflare Rocket Loader rewrites script types and defers them — it delayed the theme script past first paint. ## Performance Conventions

- `<meta charset>` must be the first element in `<head>` (within first 1024 bytes per spec)
- LCP image is preloaded via `<link rel="preload">` in `<head>`
- No deferred rendering of sections (`content-visibility`): it was removed in v4.1.0 — see CSS Architecture. Do not bring it back without checking the focus rings at a section's edges
- Scroll handlers must use rAF throttling, never raw scroll events
- `_headers` defines `Cache-Control: immutable` (1 year) for images, fonts, `/ds/*`, `styles.css`, and `script.js` — the latter two are safe to cache forever because every reference carries a content-hash `?v=` minted by `scripts/version-stamp.py`
- Pages never CDN-caches a URL with a query string, so a zone **Cache Rule** («s.morgunov.tech versioned assets (?v=) eligible for cache»: host `s.morgunov.tech`, path `/ds/*` or `/styles.css` `/script.js` `/admin-app.js` `/admin-app.css`) marks them eligible; the query string stays in the cache key, so a new `?v=` is a new object. A second Cache Rule, last in order («s.morgunov.tech unversioned /ds and share cards: never from the edge cache», 2026-11-25): host `s.morgunov.tech`, no `v=` in the query, path under `/ds/` or `/images/og-card-` → **Bypass cache**. `_headers` cannot see a query string, so these paths go out as `immutable` for a year with or without `?v=`, and the edge kept the plain address across releases: ten hours after v1.5.0 `/ds/v1/tokens.css` answered with the old bytes or the new depending on the edge node, and the share cards of v1.4.1 needed a manual purge. With the rule the plain address is always the current deployment (`cf-cache-status: DYNAMIC`). The response still carries the year-long `Cache-Control` — the rule's Browser TTL does not apply to a bypassed response (measured) — so a browser that opened the plain address keeps its copy; pages and services never do, they link with `?v=`. Function-rendered HTML always reports `cf-cache-status: DYNAMIC` — its cache is `x-edge-cache`, which zone analytics do not count. `_routes.json` excludes all static assets from Pages Functions — they serve from the CDN without a worker invocation. `/llms.txt` and `/404` are Functions (live counters / real 404 status) and therefore not excluded

- **Edge cache** (`_lib/cache.js`): every Function-rendered GET (managed pages, `/llms.txt`, notes, feeds, sitemap) is stored in `caches.default` for `EDGE_TTL` (300 s) under `origin + pathname`; `purge()` runs on every KV write — `save.js` (the page's URLs via `PAGE_PATHS` / `articlePaths`), article create/delete/import, and the subscriber ingest (`/`, `/en/`, `/llms.txt`). Responses carry `x-edge-cache: HIT|MISS`. `cached(ctx, render)` is the wrapper; `getOrHead()` sits outside it.
- **Build mark:** the footer shows the release, `vX.Y.Z` — `VERSION` in `_lib/site.js`, stamped by `version-stamp.py` from the top entry of `CHANGELOG.md` into `site.js` and into the `<a class="v4-build">` of every page — as a link to `CHANGELOG.md` on GitHub (`CHANGELOG_URL`); the rule for the family is «Build mark» in `ds/v1/USAGE.md`. The deployed commit is no longer on the page: `buildOf(env)` reads `CF_PAGES_COMMIT_SHA` (fallback: the stamped `BUILD`) and `_middleware.js` sends it as the `X-Build` header of every managed page; the `{build}` prose placeholder still resolves from it. Add the CHANGELOG entry **before** running `version-stamp.py`, or the pages are stamped with the previous version (`tests/composition.test.mjs` fails). **The footer is one module** (`ds/v1/USAGE.md`, «Footer»): under a hairline, a quiet 14px line — name · year · the build mark, then a slot of at most two links of the page's own (here one since v3.0.0: «Сказать спасибо или сообщить об ошибке» → `/thanks`), the privacy line as a nameplate on the right (11px caps in a thin frame — the way a maker's plate sits on a device; under the line on a phone; v4.1.0), and nothing else — `tests/composition.test.mjs` counts the links on every page. A third link goes on the page, not in the footer.
- **Sessions** (`_lib/auth.js`): HMAC tokens carry `iat`; «Выйти» writes `session:not-before` to KV and `verifySession(secret, token, env)` rejects anything issued earlier — a captured token dies on logout.
- `_lib/` — `content` (KV→seed load, `loadSubscribers`), `migrations` (`fixStaleContent` — code-side string fixes for KV docs, the `STALE` table and `SEED_FILL` are empty since v4.0.1; no seed import so tests load it directly), `cache` (edge cache + purge), `tg/` (Telegram publish/import: `plan`, `source-post`, `tg-html`, `tg-import`, `targets/`), `i18n`, `markdown` (zero-dep subset), `notes-feed` (the /notes feed: own notes + external materials, and the topics — `topicsOf`, `liveTopics`, `topicNavHtml`, `notesList` for `llms.txt`; pure — Node-testable), `render` (component renderers, `counters()`/`unitFor()` — the single source for every subscriber number incl. RU plural), `render-notes` (the /notes pages, feeds and `renderSitemap`), `render-article` (one note/article page), `articles` (KV articles: load, list, slugs), `article-template` (notes/article shells built from shared chrome helpers), `sanitize` (HTML sanitizer for verbatim blocks and article bodies), `overlay` (HTMLRewriter handlers), `jsonld` (home `@graph` + `renderPageJsonLd` for collaborate/about/uses), `site` (`ORIGIN`, `NAME` per language), `tg-adapter` (glue between the admin API and `tg/`), `auth`, `ai`, `http`.
- `llms.txt.js` — `/llms.txt` with live counters; `404.js` — `/404` with a real 404 status (`notFound()` sets noindex + Cache-Control itself — `_headers` never reaches Function responses). GET-only routes (sitemap, notes, feeds, `/assets/*`) are wrapped in `getOrHead()` from `_lib/http.js` so HEAD answers like GET.
- **No read-time migrations today.** On 2026-11-09 (v1.0.1) the `home` and `about` KV docs (about retired in v4.0.0) were saved with every earlier migration and copy fix applied (they carry `migration: 31`); `collaborate` and `uses` have no KV doc and render from the seed. A KV doc keeps winning over the seed, so: a **field the renderer starts reading** that an older KV doc lacks is filled from the seed at read time — `SEED_FILL` / `fillFromSeed` in `migrations.js` (v2.2.3 filled `home.sections.products.privacy`; empty since the home doc was saved again through /admin on 2026-11-25, rev 34, v4.0.1), only when missing, until an /admin Save stores it (a template element moved into a renderer is exactly this case — check the live KV doc before moving one); a **copy** fix to a KV doc goes into the `STALE` table of `migrations.js` (rules in its header) until the next `/admin` Save persists it, then the entry is removed; a **shape** change needs a gated read-time migration again (pattern: v0.31.1 `homeV2` in git history) or a Save of the new shape. `validateHome` in `admin/api/save.js` lists the sections a home doc must have.
- **Seed → KV:** `scripts/kv-push.mjs <page> [--yes] [--create]` writes the seed doc to KV the way an /admin Save does (rev + 1, `updatedAt`/`dateModified`, `:rev:<n>`, the `:revs` index of 20); dry run by default, refuses to race a concurrent Save, does not purge the edge cache (pages update within 300 s). It replaces the whole doc, so /admin edits missing from the seed are lost — the dry run lists them; the previous revision stays in /admin's history. The owner runs it.
- **Notes → KV:** a note lives only in KV — there is no seed for it. `scripts/kv-patch-notes.mjs <patch.json> [--yes]` applies a file of exact text corrections (`{ "notes": { "<slug>": [ { "field": "body.ru", "from": "…", "to": "…", "why": "…" } ] } }`) the way an /admin Save does: rev + 1, `updatedAt` / `dateModified`, a `:rev:<n>` copy, the `:revs` index, the note's row in the `articles` index. `from` must occur in the field exactly once (or `count` times) — otherwise the note is skipped whole and reported; dry run by default; a second run changes nothing. A file that was applied stays in `scripts/patches/`. The owner runs it.
- **Product cards ← GitHub:** `scripts/sync-products.mjs [--write]` updates `home.sections.products.items[]` and the /privacy tools (`privacy.sections.tools.items[]`) that carry a `repo` — a product on both pages reads the same: the version (highest of latest release, tags, `package.json`, `pyproject.toml`, the top `CHANGELOG.md` heading → `vMAJOR.MINOR`) and the description (EN = the repo description, RU = `README.ru.md` H1 tail + first paragraph; only when both exist). Order, names, tags and buttons stay hand-edited in the seed. A web product with an English page has a localized button `href` — `{ru: "https://<host>/", en: "https://<host>/en/"}` (Found You, Fingerprint since v1.2.5; Good Pass left the page in v1.2.9): their roots are Russian, so `/en/` and `llms.txt` link the `/en/` page. A product with a page on this site links that page by its path — Social Tracker: `{ru: "/social-tracker", en: "/en/social-tracker"}` (v4.4.0), TofsDevOps: `{ru: "/tofsdevops", en: "/en/tofsdevops"}` (v4.5.0) — the card's name opens it in the same tab with no «↗», and JSON-LD names the absolute URL (`absUrl` in `_lib/jsonld.js`). Then `render-static.mjs --write` and, after the merge, `kv-push.mjs home`.
- `{build}` inside `data-cms-html` prose resolves to `BUILD` from `_lib/site.js` (stamped by `version-stamp.py`) — never store a literal build hash as content.
- `admin/` — `_middleware.js` (session gate), `login`/`logout`, `index` (editor shell), `api/{content,save,preview,upload,translate,proofread,subscribers,history,articles,import,tg-preview,tg-publish,tg-archive-import}`.
- `assets/[[path]].js` — public read-only R2 delivery at `/assets/*` (no listing).
- `api/ingest/subscribers.js` — token-guarded SocialBot ingest → KV `stats:subscribers` (Telegram, YouTube, LinkedIn required; Instagram optional since v4.7.0 — the total of `counters()` is the sum of the channels shown, a channel the live record lacks counted with the doc's own value).

**Hook vocabulary** (invisible, structural-sync-safe — `check-sync.py` ignores `data-*`): `data-cms-text`, `data-cms-md`, `data-cms-href` / `data-cms-content` / `data-cms-alt`, `data-cms-abs` (absolute og/twitter image), `data-cms-img` + `data-cms-preload` (swap hero portrait when set, else keep template `srcset`), `data-cms-list="<slot>"` (regenerate a list), `data-cms-jsonld`.

**Content model:** per-page JSON doc; localizable fields are `{ru,en}`; **every text leaf is the same markdown subset** (`**bold**`, `` `code` ``, `[text](url)`, literal NBSP; block prose adds paragraphs and `- ` lists) and goes through `renderInline`/`renderProse`, which escape — there is no raw-HTML leaf in the structured docs (v0.30 converted /uses and /collaborate; `hero.ctas` remain verbatim HTML blocks sanitized on save). One `card()` helper renders home products, /uses software and /collaborate tiers. Internal hrefs may be localized. `meta`/`share`/`seo` drive `<title>`, og/twitter, and JSON-LD — **single source of truth**, so one edit updates every SEO signal (ends manual-sync drift). The subscribers stat reads live KV (`stats:subscribers`) when `auto !== false`; its RU unit is declined from the live total («подписчик/подписчика/подписчиков»). **Counters:** every subscriber number comes from one `counters()` — the stats strip, the /notes channel panel (the Telegram count, its Russian noun declined by `pluralRu`; no placeholder in the doc since v4.1.0) and `llms.txt`, whose template may contain `{telegram}`, `{linkedin}`, `{youtube}`, `{total}`. **Product schema:** `products[].schema {type, category, os, license, free}` overrides the JSON-LD item (default `WebApplication` / `PrivacyApplication` / `Web`, free). **KV vs seed:** a KV doc wins over the seed; the seed is the fallback and the static twins' source (see «No read-time migrations today» above). Editor client: root-level public `admin-app.js` + `admin-app.css` (no secrets), vanilla, **inline edit-in-place** (Egea/Notion-style, v0.25) — the server-rendered live-preview iframe *is* the editor: click text to edit it on the page; markdown leaves get a floating Bold/Link bar; verbatim-HTML section blocks and images open popovers; lists show a hover ↑↓✕ toolbar + "+ добавить". Non-inline fields (`<title>`/meta, share card + preview, SEO/JSON-LD, subscribers `auto`) live in a slide-over **Settings drawer**. The in-memory doc is the single source of truth — text edits write straight back (caret survives); structural edits re-render from it. Per-field **AI** (RU→EN, Вычитать = proofread+typography, non-destructive) in the drawer and on the floating bar. As of **v0.26**: the toolbar floats by the focused field; the site's own header RU/EN + theme controls drive editing; **Save auto-syncs changed RU→EN** (hand-edited EN is protected); **undo/redo** (⌘Z) + **«Откатить»** + **version history** (restore a past revision from the drawer); `/uses` card images are click-to-upload.

**Privacy contract preserved on public pages:** no cookies, trackers, analytics, or AI calls. The session cookie is `HttpOnly; Secure; SameSite=Strict; Path=/admin` — never sent on public pages. AI runs server-side only, key never on the client.

**Build/deploy:** still no build step or npm committed for the static site; Pages bundles Functions on push. `wrangler.toml` declares bindings `CONTENT` (KV) + `MEDIA` (R2). Secrets via `wrangler pages secret put`: `ADMIN_PASSWORD_HASH` (generate with `scripts/hash-password.mjs` — PBKDF2 at 100 000 iterations, the most Workers' Web Crypto accepts; a 600 000-iteration hash throws there and locked the owner out until v2.1.1; the secret reaches the site with the next deployment), `SESSION_SECRET`, `ANTHROPIC_API_KEY`, `SOCIALBOT_INGEST_TOKEN`, and for publishing notes to the channel `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHANNEL`.
